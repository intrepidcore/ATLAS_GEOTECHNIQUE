BienCorrection du bug commit SQLAlchemy (transaction non fermée) — c'était la cause racine du blocage de plusieurs heures
RisqueLe correctif wp='-' → 0.0 dans _parse_float est scientifiquement dangereux. Dans limite.xlsx, '-' signifie "non mesuré", pas "zéro". WP=0.0 donne IP = WL - 0 = WL, ce qui est physiquement faux (un sol avec IP = WL serait entièrement liquide à la limite de plasticité). Il faut garder None pour ces cas et ne pas les insérer.
Detteip_generated = wl - wp calculé en Python avant insert, mais pas garanti par un trigger DB. Si WP est mis à jour ultérieurement, ip_generated dérive silencieusement.

Correction recommandée

  • Remettre '-' → None dans _parse_float
  • N'insérer que si wl IS NOT NULL OR wp IS NOT NULL (pas les deux nuls)
  • Ajouter trigger PostgreSQL : ip_generated = CASE WHEN wl IS NOT NULL AND wp IS NOT NULL THEN wl - wp END
