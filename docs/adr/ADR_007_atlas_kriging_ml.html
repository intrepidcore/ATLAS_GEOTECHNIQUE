ADR-004 · Atlas Géotechnique
Stratégie d'interpolation géostatistique hybride et pipeline ML/ONNX
Accepté 2026-03-30 Plateforme scientifique Pipeline IA

Contexte

Atlas produit des cartes géotechniques nationales (Togo) à partir de sondages discontinus. Le pipeline actuel réalise un kriging global national sur quelques paramètres (IP, VBS), avec une logique d'inférence rule-based. Deux problèmes bloquent la maturité scientifique de la plateforme :

  • Le kriging viole la stationnarité en mélangeant des formations géologiques hétérogènes dans un même variogramme.
  • L'endpoint /ai/infer/maille n'est pas apprenant — il dérive des règles déterministes, non d'un modèle entraîné.

Cet ADR formalise les décisions architecturales pour corriger ces deux limitations et établir un pipeline défendable à niveau publication/mémoire.

Décision 1 — Domaine d'interpolation : géologie/pédologie, pas les dépressions

Problème

Le kriging suppose une stationnarité intrinsèque : Z(s) = μ + ε(s), Var[Z(s₁) − Z(s₂)] = 2γ(h) où γ(h) ne dépend que de la distance h, pas de la position absolue. Les dépressions morphologiques ne couvrent pas 100 % du territoire et ne définissent pas des domaines physiquement homogènes — le variogramme calculé sur une telle partition est statistiquement invalide.

AlternativeCouvertureStationnaritéVerdict
Kriging national unique100 %Non — mélange formationsBiais fort, RMSE élevé
Kriging par dépressionsPartielleNon — discontinuités spatialesZones blanches + variogramme invalide
Kriging stratifié géologie/pédologie retenu100 %Oui — domaines physiquement homogènesConforme BRGM / AFSIS / USGS

Décision 2 — Architecture des domaines : table atlas.kriging_domains

Schéma cible
CREATE TABLE atlas.kriging_domains (
  id            uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  domain_type   text NOT NULL CHECK (domain_type IN ('geologie','pedologie','risque_gonflement')),
  domain_code   text NOT NULL,
  geom          geometry(MultiPolygon, 4326) NOT NULL,
  created_at    timestamptz DEFAULT now(),
  UNIQUE (domain_type, domain_code)
);
CREATE INDEX ON atlas.kriging_domains USING GIST (geom);

Le pipeline assigne chaque maille à son domaine via ST_Contains(kd.geom, maille.centroid). Un maille sans domaine tombe en fallback domaine national (comportement dégradé documenté, non silencieux).

Décision 3 — Pipeline kriging scientifique avec traçabilité obligatoire

Pipeline officiel
extract stats maille par domaine
→ compute variogram auto-fit (nugget, sill, range, anisotropy)
→ cross-validation LOO + block (k=5)
→ kriging ordinaire par domaine
→ régression kriging ML (niveau 2, optionnel)
→ fusion mosaïque nationale
→ store run metadata (atlas.ai_variograms)
→ update vue thématique (v_latest_ai_interpolation)

Table de traçabilité atlas.ai_variograms — champs obligatoires

range_m       float   -- portée (mètres)
sill          float   -- palier
nugget        float   -- effet pépite (ratio nugget/sill recommandé < 0.25)
model_type    text    -- spherical | exponential | gaussian | matern
anisotropy    jsonb   -- {ratio, direction_deg}
fit_score     float   -- R² ajustement variogramme empirique
loo_rmse      float   -- LOO cross-validation RMSE (critère acceptation)
block_rmse    float   -- block CV RMSE k=5
support_points int    -- nb points utilisés
domain_code   text    -- domaine parent
parameter_id  text    -- paramètre interpolé
run_id        uuid    -- lien atlas.ai_model_registry

Critère d'acceptation : loo_rmse < sill × 0.35 — sinon le run est marqué quality_flag = 'degraded' et non publié par défaut.

Décision 4 — Inférence ML temps réel via microservice ONNX

Problème

L'endpoint /ai/infer/maille dérive actuellement des règles déterministes. Ces règles sont non-apprenantes, non-auditables, et exposent une fausse promesse "IA" à l'utilisateur.

AlternativeLatenceMaintenabilitéVerdict
Rule-based conservé< 5 msForte — SQL/Rust purNon apprenant, dette scientifique
Inférence Python inline (subprocess)200–500 msFaible — couplage fortFragile, non scalable
Microservice atlas-api-infer + ONNX retenu10–30 msForte — découplé, versionnéStandard industrie, fallback possible

Logique de fallback obligatoire

if atlas_api_infer.health() == OK and model_registry.has_valid_model():
    prediction = onnx_inference(features)
    source_type = "ml_infer"
else:
    prediction = rule_based_fallback(features)
    source_type = "deterministic"
    log.warn("ONNX unavailable, fallback activated")

Le champ source_type est propagé jusqu'à l'UI — l'utilisateur voit toujours la provenance de la valeur.

Décision 5 — Architecture UI : mode standard + mode expert domaines

Principe

Le kriging stratifié produit N surfaces partielles fusionnées en une mosaïque nationale. L'utilisateur standard voit une carte unique. L'expert accède aux domaines individuels pour validation scientifique.

Règle d'affichage source_type (non négociable)

mesure        → point plein, symbologie primaire
kriging       → point semi-transparent + hachure légère
ml_infer      → point semi-transparent + badge "IA"
deterministic → point semi-transparent + badge "Est."

Aucune valeur interpolée ou inférée ne s'affiche sans indicateur visuel de sa provenance. C'est une règle de sécurité métier, pas une option UX.

Conséquences

Gains
  • Variogrammes scientifiquement valides par domaine
  • Reproductibilité publication / mémoire
  • Inférence apprenante et auditable
  • UI : transparence source pour l'ingénieur terrain
  • Couverture 100 % territoire garantie
Coûts et risques
  • Migration DB : table kriging_domains + ai_variograms
  • Mismatch UI/source à corriger (v_latest_ai_interpolation)
  • Nouveau service atlas-api-infer à déployer et maintenir
  • Charge pipeline x3–x5 (N domaines vs 1 national)
  • Risque : mailles aux frontières de domaines (à tester)

Critères d'acceptation mesurables

AC-01Kriging exécuté uniquement sur domaines géologiques/pédologiques — zéro run national non stratifié
AC-02Chaque run stocke loo_rmse, block_rmse, nugget, sill, range_m dans ai_variograms
AC-03loo_rmse < sill × 0.35 pour publication — sinon quality_flag = 'degraded'
AC-04Couverture mosaïque nationale ≥ 99,9 % des mailles (fallback domaine national pour le reste)
AC-05Toute valeur affichée en UI porte un source_type visible — zéro valeur sans indicateur de provenance
AC-06atlas-api-infer health check OK avant chaque inférence — fallback rule-based loggé si indisponible
AC-07WL, WP, passant_2mm, passant_20mm activés dans ai_parameter_catalog avec mapping PARAM_TO_STATS_COL validé
