ADR-006 · Atlas Géotechnique
Protocole d'import données géotechniques terrain — garantie de qualité pipeline ML
Accepté 2026-03-30 Import / ETL Qualité données Anti-régression obligatoire

Contexte

L'incident AMESSEFE a révélé trois classes de défaillances d'import silencieuses : localite_key tronqué causant des collisions de clés, depth_m pollué par des valeurs CG, et des essais VBS/Atterberg non rattachés malgré leur présence dans les fichiers raw. Ces défaillances ont réduit le support kriging de ~200 points attendus à 27 points exploitables, sans aucune alerte.

Règle fondamentale : tout import sans gate de validation automatique est interdit. Un import silencieux qui réussit mais corrompt les données est pire qu'un import qui échoue.

Décision 1 — Pipeline d'import en 5 gates obligatoires

G-01
Validation structure fichier source (colonnes obligatoires, types, plages)
↓
G-02
Normalisation identifiants (localite_key, sondage_code, source_label)
↓
G-03
Validation plages physiques (depth_m, IP, VBS, WL, WP, CG)
↓
G-04
Rattachement géospatial (sondage → maille, vérification geom valide)
↓
G-05
Rapport de couverture pré/post import (delta VBS, IP, WL, WP, CG)
↓ si tous gates OK
✓
Commit en base + trigger recalcul feature store
↓ si un gate échoue
✗
ROLLBACK total + rapport d'erreur détaillé — aucun écrit partiel

Décision 2 — Règles de validation par champ (gate G-01 et G-03)

depth_m — profondeur échantillon
Plage valide : 0.0 ≤ depth_m ≤ 15.0 m. Valeurs > 10 m → warning + flag depth_unusual. Valeurs > 15 m → rejet.
Contrôle croisé : si depth_m > 3.5 ET paramètre associé dans plage CG → alerte collision probable, blocage import de la ligne.
IP — indice de plasticité
Plage valide : 0 ≤ IP ≤ 100. IP > 80 → warning (vertisol/bentonite, à documenter). IP > 100 → rejet.
Contrôle cohérence : IP doit être ≤ WL − WP si les trois sont présents (sinon erreur de calcul ou saisie).
localite_key — clé de rattachement localité
Généré systématiquement par : LOWER(REGEXP_REPLACE(UNACCENT(TRIM(localite_libelle)), '[^a-z0-9]+', '_', 'g')). Jamais saisi manuellement. Unicité vérifiée avant insert.
Si collision détectée (même localite_key, libellés différents) → rejet avec liste des conflits.
VBS — valeur de bleu de méthylène
Plage valide : 0.0 ≤ VBS ≤ 15.0 g/100g. VBS > 10 → warning. Corrélation attendue avec IP : si IP > 30 et VBS < 0.5 → alerte incohérence.
CG — potentiel de gonflement
Plage valide : 0.0 ≤ CG ≤ 20.0 %. Stocké exclusivement dans essais_potentiel_gonflement. Jamais dans echantillons.depth_m.

Décision 3 — Normalisation localite_key (non négociable)

-- Fonction canonique de génération localite_key
-- À utiliser dans TOUS les parsers d'import, sans exception
CREATE OR REPLACE FUNCTION atlas.normalize_localite_key(libelle text)
RETURNS text AS $$
  SELECT LOWER(
    REGEXP_REPLACE(
      UNACCENT(TRIM(libelle)),
      '[^a-z0-9]+', '_', 'g'
    )
  );
$$ LANGUAGE SQL IMMUTABLE;

-- Contrainte d'unicité en base
ALTER TABLE public.sondages
  ADD CONSTRAINT uq_localite_source 
  UNIQUE (localite_key, source);

Tout parser d'import doit appeler atlas.normalize_localite_key(). Un parser qui génère localite_key autrement est considéré non conforme et bloqué en CI.

Décision 4 — Rapport de couverture obligatoire post-import (gate G-05)

-- Généré automatiquement après chaque import réussi
-- Stocké dans atlas.import_coverage_log
INSERT INTO atlas.import_coverage_log (
  import_id, source_label, run_at,
  n_sondages_before, n_sondages_after,
  n_vbs_before, n_vbs_after,
  n_ip_before, n_ip_after,
  n_wl_wp_before, n_wl_wp_after,
  n_eg_before, n_eg_after,
  n_maille_linked_before, n_maille_linked_after,
  delta_vbs, delta_ip, delta_eg
) VALUES (...);

Si delta_vbs < 0 ou delta_ip < 0 après import : l'import est rejeté automatiquement — un import ne peut jamais faire régresser la couverture.

Décision 5 — Trigger automatique pipeline après import validé

-- Après commit import réussi :
1. atlas.refresh_feature_store()           -- mise à jour feature store mailles
2. POST /ai/recompute/sources              -- recalcul sources IA
3. Enqueue job 'kriging_recompute'         -- kriging stratifié par domaine
4. Enqueue job 'regression_kriging'        -- RK si n_support suffisant
5. Enqueue job 'ml_train_supervised'       -- retrain si delta_points > seuil

-- Les jobs sont en queue (SKIP LOCKED), non bloquants
-- Notification UI : "Import validé — 3 jobs enqueués"

Décision 6 — Tests de non-régression obligatoires en CI

tests/import/
  test_localite_key_no_collision.py      -- unicité garantie
  test_depth_m_range.py                  -- 0–15m strict
  test_no_cg_in_depth_column.py          -- contrôle croisé CG/depth
  test_ip_wl_wp_coherence.py             -- IP ≤ WL - WP
  test_coverage_delta_positive.py        -- delta VBS/IP/EG ≥ 0
  test_rollback_on_gate_failure.py       -- aucun écrit partiel

Ces tests tournent sur des fixtures de données synthétiques incluant les cas d'échec AMESSEFE documentés. Ils font partie du CI obligatoire — un PR qui les casse est bloqué.

Critères d'acceptation

AC-01Tout import sans les 5 gates est rejeté au niveau CI — aucun parser non conforme en production
AC-02Zéro collision localite_key après import — vérifiable par COUNT(DISTINCT localite_key) = COUNT(DISTINCT libelle) par source
AC-03Zéro valeur CG dans la colonne echantillons.depth_m — vérifiable par requête de contrôle automatique
AC-04delta_vbs ≥ 0 et delta_ip ≥ 0 après tout import — sinon rollback automatique
AC-05Rapport import_coverage_log produit et consultable en UI Admin dans les 30s post-import
AC-06Jobs kriging/RK/ML enqueués automatiquement après import validé — aucun retrain manuel requis
AC-076 tests de non-régression passent sur les fixtures AMESSEFE en CI
