BienLa correction est scientifiquement correcte. WP=None pour les non-mesurés signifie que ces localités n'auront pas d'IP calculé — ce qui est honnête plutôt que de propager un IP faux.

BienLe script gère maintenant les doublons echantillons par depth_m (mise à NULL des profondeurs hors Excel). Le health check par profondeur (verify_amessefe_wl_wp_ip_health.py) est la bonne approche — évite le biais des moyennes.

FIX-3is_ked_parameter() + v_latest_ai_interpolation — architecturalement correctSolide
Bienis_ked_parameter basé sur le suffixe _ked_h* est extensible sans modification pour P4/P5. Migration 168 avec is_superseded et priorité explicite est le bon pattern.
RisqueLa vue v_latest_ai_interpolation utilise ROW_NUMBER() OVER (PARTITION BY maille_id, parameter_id ORDER BY priority, created_at DESC). Si deux runs KED existent pour le même paramètre/maille (ex: re-run après correction), les deux auront is_superseded=false et le tie-breaker sera created_at DESC. Il faut s'assurer que chaque nouveau run KED met is_superseded=true sur les valeurs précédentes du même paramètre avant d'insérer.
Gap ADMLe workaround pour ms.adm2_name dans routes.rs a nécessité 4 itérations — signe que la construction dynamique de SQL par string concatenation dans ce handler est fragile. À terme, migrer vers sqlx QueryBuilder avec paramètres typés.
