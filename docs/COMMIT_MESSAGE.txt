feat: Migration UI vers granularité sondage individuel

Bascule complète de l'UI du géocodage de la granularité "localité agrégée"
vers "sondage individuel" pour une gestion plus précise et conforme aux
décisions d'architecture.

## Backend (Rust)

### Nouveau module `sondages.rs`
- GET /sondages - Liste paginée avec filtres (search, missing)
- GET /sondages/stats - Statistiques (total, geocoded, with_geom, with_adm3)
- GET /sondages/:id - Détails d'un sondage
- PATCH /sondages/:id/geometry - Mise à jour géométrie (mode: adm|exact)
- GET /sondages/:id/adm3-candidates - Suggestions ADM3 par similarité

### Caractéristiques
- Retourne 230 sondages individuels (vs 1 localité agrégée)
- Flag `is_geocoded` calculé automatiquement (generated column)
- Pagination et filtres dynamiques
- Validation des payloads PATCH

## Frontend (TypeScript)

### Nouveau client API `api/sondages.ts`
- Interfaces typées (Sondage, SondagesStats, Adm3Candidate)
- Fonctions: listSondages, getSondagesStats, getSondage, updateSondageGeometry
- Helper: extractLocaliteFromCode, formatGeocodeLabel
- Helper global: apiPatch() ajouté dans surveys-canon.ts

### UI Modifiée

#### Modal Sondages (`sondages-modal.ts`)
- Affiche 230 sondages individuels (pas 1 localité)
- Suppression badge "X sondages"
- Label "Géocodé : Oui/Non" préservé
- Titre JSON: "Objet sondage" (au lieu de "canonique")
- Toast non-bloquant au lieu d'alert()
- Import toast utility

#### Panneau Géocodage (`geocode-canon-panel.ts`)
- Titre: "Sondages sans géométrie" (au lieu de "Villages")
- API /sondages (au lieu de /surveys-canon)
- Toast non-bloquant pour erreurs
- Clic sur suggestion ADM3 pré-sélectionne le select
- Rafraîchissement immédiat des stats après PATCH
- Toast de succès avec nom du sondage

#### Panneau Suggestions (`suggestions-canon-panel.ts`)
- KPI: "Total sondages" (au lieu de "Total villages")
- Suppression pilule "unknown" dans la liste
- Pilule conservée dans la fiche détail (Mode: unknown)
- API /sondages
- Logs console: "[SONDAGES]"
